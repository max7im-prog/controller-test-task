Представьте, что Raspberry Pi отправляет команды управления на второе устройство (условный «контроллер»), которое принимает команды и выполняет их.

# **Задание**

## **1. Реализовать двусторонний канал связи**

Создать класс:

```cpp
class VirtualSerial {
public:
    void sendAtoB(const std::vector<uint8_t>& data);
    void sendBtoA(const std::vector<uint8_t>& data);

    bool readA(std::vector<uint8_t>& out);
    bool readB(std::vector<uint8_t>& out);
};

```

Это **две очереди сообщений**.

### Требования:

- потокобезопасность (mutex + condition_variable или lock-free структура)

- неблокирующие методы readA/readB (возвращают false если данных нет)

## **2. Определить протокол управления**

Пакет — структурированный бинарный формат:

| Поле | Тип | Описание |
| --- | --- | --- |
| header | `uint8_t` | 0xAA |
| version | `uint8_t` | версия 1 |
| command_id | `uint8_t` | команда |
| payload_len | `uint8_t` | количество байт данных |
| payload | `N bytes` | аргументы команды |
| crc16 | `uint16_t` | CRC-16/X25 |

CRC должен быть **реально посчитан**, а не фиктивным XOR.

## **3. Команды**

Реализовать **3 команды от A к B**:

### `0x10` — Установить PWM значение

payload:

```
uint16_t pwm_value

```

### `0x20` — Установить PID коэффициенты

payload:

```
float kp, ki, kd

```

### `0x30` — Запрос статуса

payload: пусто


## **4. Ответы устройства B**

Устройство B отвечает сообщениями:

| Поле | Command ID | Payload |
| --- | --- | --- |
| `0x81` | подтверждение PWM, payload = принятый pwm_value |  |
| `0x82` | подтверждение PID, payload = kp, ki, kd |  |
| `0x83` | статус (random simulated): батарея %, температура °C |  |

## **5. Многопоточность**

Требуется **два потока**:

### Поток 1 — Device A

Поток 2 — Device B

- Читает команды от A

- Парсит протокол

- Выполняет (симулирует)

- Отправляет ответ

## **6. Обязательные элементы**

Кандидат должен написать:

- сериализатор/десериализатор пакетов

- CRC-16

- потокобезопасный виртуальный канал

- два потока-устройства

- логирование действий

- корректную обработку ошибок (невалидный CRC, неправильная длина, неизвестная команда)
